7.1 Hardware

Physical computers 7.1.1

TypeFeatures/useTypical suitability factors
Personal computerGeneral-purpose computer for individual users and a wide range of applications.Suitable where a user needs flexible local processing, storage and peripherals.
Mobile devicePortable smartphones/tablets designed for mobile use.Useful where portability, wireless access and mobile applications matter.
ServerProvides resources or services to other computers/users.Used for shared services, data, applications or network resources.
Embedded deviceComputer built into another product to perform a dedicated or limited set of functions.Suitable for control/monitoring tasks where a full general-purpose computer is unnecessary.

Hardware devices 7.1.2

HardwareKey knowledge
Input devicesSend data or control signals into a computer system.
Output devicesPresent or deliver processed information from a computer system.
ProcessorExecutes instructions. Specification factors include number of cores, clock speed, cache size and mobile processors.
RAMMain memory used for data/instructions currently required during operation; volatile.
ROMMain memory used for instructions/data intended to persist without power.
Secondary storagePersistent storage. Types required: magnetic, solid-state and optical.
MotherboardMain circuit board that connects and enables communication between computer components.
GPUProcessor specialised for graphics and highly parallel processing tasks.
Network interface devicesSpecification includes PCI and USB interfaces/devices for connecting hardware/network capability.
CoolingAir and liquid cooling remove heat to support reliable operation.
SensorsDetect physical/environmental conditions and provide input data to a system.
Application focusQuestions can require students to relate hardware features to the needs of a particular digital system rather than merely name components.

7.2 Software

Operating systems 7.2.1

OS typeSpecified features/use
BatchNon-interactive applications, high-volume processing and scheduling.
MultitaskingConcurrent execution of multiple tasks using time-slicing and interrupts.
Real-timeMonitoring/control applications and transaction processing where timely responses matter.
NetworkResource sharing, user management and communication across a network.
MobileDesigned for smartphones/tablets, lower processing requirements and increased battery life.

Utilities 7.2.2

UtilityFeature/use
File managementOrganises and manages files/folders.
DefragmenterReorganises fragmented data where relevant to improve storage access.
File compressionReduces file size for storage or transfer.
Package managerSupports installation/management of software packages.
Protection softwareHelps protect systems from software/security threats.

Code-development tools 7.2.3

  • IDE: may provide code editing, debugging and screen-design tools.
  • Compiler: translates source code into another executable/machine-oriented form before execution.
  • Interpreter: translates/executes program instructions during execution.

Application software 7.2.4

Students must understand features and uses of word processors, spreadsheets, databases, email and project-management software.

Common misconceptionSystem software and application software serve different purposes. Do not describe an operating system as a normal end-user application.

7.3 Networks

Benefits and drawbacks of networking 7.3.1

BenefitsDrawbacks
Resource/data sharing, communication and centralised access to services.Dependence on network availability, security exposure, administration and infrastructure requirements.

Network types 7.3.2

TypeFeature/scope
PANConnects devices over a personal, short-range area.
LANConnects devices across a limited local area.
MANConnects systems across a metropolitan-scale area.
WANConnects networks/devices across large geographical areas.
VPNCreates a protected private connection over another network.

Selection can consider number of users, connection media and coverage.

Connectivity methods 7.3.3

MethodFeaturesBenefits/drawbacks
Copper/EthernetWired electrical connection.Stable physical connection; cabling limits mobility.
Fibre-opticWired connection using light.Supports high-capacity transmission; installation/equipment requirements may be greater.
Wireless access pointAllows wireless devices to connect to a network.Mobility and convenient access; performance/security can depend on environment/configuration.

Topologies 7.3.4

TopologyFeatureBenefitDrawback
StarDevices connect through a central point.Individual links can be managed independently.Central infrastructure is important to operation.
MeshDevices/nodes can have multiple interconnections.Alternative routes can improve resilience.More connections increase complexity/resources.
TreeHierarchical arrangement of connected network branches.Supports structured expansion.Higher-level failures may affect dependent branches.

Physical topology describes actual connections; logical topology describes how data moves through the network.

Network models 7.3.5

ModelFeaturesBenefits/drawbacks
Client-serverClients request services/resources from servers.Centralised management/services, but server/infrastructure dependency and administration are required.
Thin clientClient depends heavily on central/server resources.Can simplify endpoint management; increases dependency on network/server services.
Peer-to-peerDevices can share resources directly without relying on a dedicated central server for all sharing.Simple for limited sharing; harder to centrally manage as requirements grow.

Network components 7.3.6

  • Server: provides network resources/services.
  • Client: requests/uses network resources/services.
  • Router: forwards traffic between networks.
  • Network switch: connects devices and forwards traffic within a network.
  • Internet connection/backbone: provides connectivity into wider internet infrastructure.

OSI model 7.3.7

LayerCore function
7 ApplicationNetwork services used by applications.
6 PresentationRepresentation/translation of data.
5 SessionEstablishes/manages communication sessions.
4 TransportEnd-to-end transport of data.
3 NetworkLogical addressing and routing between networks.
2 Data linkLocal link transfer and framing.
1 PhysicalTransmission of signals/bits using physical media.

Students must also understand related protocols at the appropriate layers.

TCP/IP model 7.3.8

LayerCore function
ApplicationApplication-facing network protocols/services.
TransportHost-to-host transport.
InternetAddressing/routing across interconnected networks.
NetworkAccess to/transmission across the underlying network.

Packets and packet switching 7.3.9

Data is divided into packets for network transmission. Students should understand packet contents/structure, the role of packet components, packet switching, causes of packet loss and CRC error handling.

Packet conceptsPacket information supports delivery and reconstruction of data. Packet switching allows packets to travel through a network rather than reserving one dedicated end-to-end path. Packet loss means expected packets fail to arrive. A cyclic redundancy check helps detect transmission errors.

Network protocols 7.3.10

GroupProtocolsRole
WebHTTP, HTTPSTransfer web resources; HTTPS provides protected web communication.
MailSMTP, POP, IMAPSMTP sends mail; POP/IMAP support retrieval/access approaches.
RoutingRIP, OSPFSupport routing decisions/exchange of routing information.
ApplicationFTP, SFTP, DHCP, DNSFile transfer, protected file transfer, network configuration allocation and name resolution.

Bandwidth and latency 7.3.11

  • Bandwidth: capacity for data transfer over a connection.
  • Latency: delay affecting how quickly data/response travels across a network.

Higher bandwidth can support more data transfer, while high latency can make interactive/networked systems feel less responsive. Suitability depends on the application.

7.4 Virtual Environments

Components 7.4.1

  • Virtual machines: software-defined computing environments, including virtual PCs, switches, routers and servers.
  • Type 1 hypervisor: virtualisation layer operating directly on host hardware.
  • Type 2 hypervisor: virtualisation software operating through a host operating system.

Features 7.4.2

FeatureMeaning in context
Increased securityVirtual boundaries can help separate workloads.
Managed executionVirtual workloads can be controlled within managed environments.
SharingPhysical resources can support multiple virtual environments.
AggregationResources can be combined/managed to support virtual workloads.
EmulationA virtual environment can represent another computing environment.
IsolationVirtual systems can be separated from one another.
PortabilityVirtual environments can be easier to move/reproduce than equivalent physical systems.

Benefits and drawbacks 7.4.3–7.4.4

BenefitsDrawbacks
Cost effectiveness for large environments; easy management; resilience; potentially lower carbon footprint; improved disaster-recovery options; better test environments; education/training provision.Extra hardware load; slower execution time; possible false representation of performance.
Judgement focusDo not assume virtualisation is always better. Apply resource demand, testing realism, resilience and management needs to the scenario.

7.5 Cloud Environments

Cloud types 7.5.1

  • Private cloud: cloud environment dedicated to an organisation or defined user group.
  • Public cloud: cloud services/resources supplied through a provider for customers to consume.

Benefits 7.5.2

  • Portability
  • Elasticity
  • Fewer storage limitations
  • Cost effectiveness

Cloud delivery models and responsibility 7.5.3

ModelClient managesCloud provider manages
IaaSApplication software, system software/middleware/OS, runtime, data, user accounts.Virtualisation and hardware: servers, network, storage.
PaaSApplication software, data, user accounts.Virtualisation, hardware, system software/middleware/OS and runtime.
SaaSUser accounts and data.Virtualisation, hardware, system software/middleware/OS, runtime and application software.
Common misconceptionThe client does not manage the same resources in IaaS, PaaS and SaaS. Responsibility shifts progressively towards the provider.

7.6 Resilient Digital Environments

Benefits and impact 7.6.1

  • Increased security: data security in storage/transfer and reduced vulnerabilities.
  • Increased reputation: protection of brand/image and customer confidence.
  • Reduced downtime: supports continued availability of services.

Methods used to improve resilience 7.6.2

MethodPurpose/application
Software updates/upgradesPlanned updates/upgrades and patches responding to vulnerabilities.
Hardware replacementRolling replacement plans and secure disposal reduce dependence on ageing equipment.
Data/system redundancyAlternative copies/components reduce reliance on a single resource.
Device hardeningRemove unneeded ports, applications, permissions and access.
Backup/recoveryOnsite, remote/offsite and cloud approaches support restoration.
Hot/warm/cold sitesAlternative recovery locations providing different levels of readiness.
Standard operating proceduresInclude staff training, induction, new digital systems and new/updated policies.
Scenario linkHigher-demand questions should require students to select or judge resilience measures in relation to a stated risk, system requirement or organisational context.

Revision-Agent Guidance

Strict scopeGenerate questions only from Core Paper 2, Content Area 7, references 7.1.1–7.6.2. Do not drift into Security (Content Area 8) unless CA07 itself explicitly requires a security-related feature or benefit.

Question design

  • Map every question to a CA07 specification reference and appropriate AO.
  • Include knowledge questions, but favour contextual understanding, application and judgement where suitable.
  • Use realistic digital-environment scenarios: organisations, networks, cloud services, virtualisation, hardware selection and resilient systems.
  • When asking for benefits/drawbacks, require links to the scenario for higher-demand questions.
  • For protocols/models/layers, avoid testing content beyond the stated specification.
  • For IaaS/PaaS/SaaS, assess responsibility accurately.
  • Do not reveal answers before the student's attempt.

Common misconceptions to detect

  • RAM and secondary storage serve the same purpose.
  • A server is simply a more powerful personal computer rather than a system providing services/resources.
  • All operating systems work in the same way.
  • Logical and physical network topologies are identical.
  • A switch and router perform the same network role.
  • Higher bandwidth means lower latency.
  • Binary protocol names can be guessed from abbreviations without understanding purpose.
  • Virtual machines have no performance overhead.
  • Public cloud means all customer data is publicly accessible.
  • IaaS, PaaS and SaaS give clients the same management responsibilities.
  • A backup alone guarantees full resilience.

High-demand areas

  • Compare network types/connectivity/topologies/models for a scenario.
  • Explain packet transmission, packet loss and CRC.
  • Relate OSI/TCP-IP layers and protocols to network functions.
  • Judge virtual-environment suitability using benefits/drawbacks.
  • Select IaaS/PaaS/SaaS from responsibility requirements.
  • Recommend resilience measures and justify organisational impact.
