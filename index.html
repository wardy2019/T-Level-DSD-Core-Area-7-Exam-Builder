Hardware: uses, benefits and limitations

  • Personal computer: A general-purpose computer intended primarily for an individual user. Use: Desktop productivity, software development, education and local applications. Benefit: Flexible peripherals and generally easier upgrading for desktops. Drawback: Less portable than a mobile device. Example: A developer workstation running an IDE.
  • Mobile device: A portable computer such as a smartphone or tablet, normally designed for battery -powered use. Use: Communication, mobile apps, data capture and work while moving. Benefit: Portable and integrates wireless connectivity and sensors. Drawback: Smaller screens, battery constraints and usually less upgradeable. Example: A tablet used by field staff.
  • Server: A computer that provides services or resources to clients over a network. Use: Hosting files, applications, databases, websites or user services. Benefit: Can centralise resources and management. Drawback: Failure can affect many clients unless resilience is built in. Example: A file server for a college department.
  • Embedded device: A computer built into a larger product to perform a dedicated or limited set of functions. Use: Monitoring or controlling equipment. Benefit: Can be efficient and tailored to a specific task. Drawback: Usually less flexible than a general-purpose computer. Example: A controller inside a smart thermostat.
  • Input devices: Hardware used to enter data or control signals into a computer. Use: Capture user input or real -world data. Benefit: Can make data entry direct and efficient. Drawback: Suitability depends on context, accuracy and accessibility. Example: Keyboard, mouse, microphone, camera or scanner.
  • Output devices: Hardware used by a computer to present or produce information. Use: Display, print, play or otherwise output processed data. Benefit: Allows users or other systems to receive results. Drawback: Choice affects cost, accessibility and quality. Example: Monitor, printer or speakers.
  • Processor - cores: A core is an independently executing processing unit within a CPU. Use: More cores can support concurrent workloads when software can use them. Benefit: Can improve throughput for suitable multitasking/parallel workloads. Drawback: More cores do not guarantee proportional performance gains.
  • Processor - clock speed: The rate at which a processor clock cycles, normally measured in hertz. Use: A factor influencing how quickly instructions can be processed. Benefit: Higher speed can improve performance within a comparable processor design. Drawback: Performance cannot be judged from clock speed alone.
  • Processor - cache: Small, fast memory used near/on the processor to hold frequently needed data/instructions. Use: Reduce the time spent waiting for slower main memory. Benefit: Faster access to frequently required data. Drawback: Limited capacity and processor performance still depends on other factors.
  • Mobile processors: Processors designed for mobile devices, where power use, heat and battery life matter strongly. Use: Run smartphone/tablet operating systems and applications. Benefit: Can balance performance with energy efficiency. Drawback: May operate under tighter power/thermal limits than larger systems.
  • RAM: Volatile main memory holding programs and data currently in use. Use: Provides fast working storage for active software. Benefit: More appropriate RAM can support larger/more concurrent workloads. Drawback: Contents are lost when power is removed.
  • ROM: Non-volatile memory whose contents persist without power and are normally used for stable instructions/firmware. Use: Store instructions needed for device start-up or dedicated operation. Benefit: Retains its contents without power. Drawback: Not intended to act as normal writable working memory.
  • Magnetic secondary storage: Stores data magnetically, commonly on hard disk drives. Use: Large-capacity persistent storage. Benefit: Often cost-effective for high capacities. Drawback: Mechanical parts can make it slower and more vulnerable to physical shock than solid-state storage.
  • Solid-state secondary storage: Stores persistent data electronically with no moving mechanical disk. Use: System drives, laptops, portable storage and fast data access. Benefit: Fast access, quiet operation and good shock resistance. Drawback: Cost per unit of capacity can be higher than magnetic storage.
  • Optical secondary storage: Uses laser-readable media such as optical discs. Use: Distribution, archive or transfer where optical media are suitable. Benefit: Removable and useful for some archival/distribution cases. Drawback: Lower capacity and slower access than many modern alternatives.
  • Motherboard: The main circuit board that connects core computer components. Use: Provides communication paths and physical/electrical connections among processor, memory, storage interfaces and expansion devices. Benefit: Integrates components into one system. Drawback: Compatibility limits which components can be fitted.
  • GPU: A processor specialised for highly parallel graphics and compute workloads. Use: Rendering graphics and accelerating suitable parallel tasks. Benefit: Can process many similar operations concurrently. Drawback: Adds cost, power use and cooling demand where a discrete GPU is used.
  • Network interface device - PCI: A network interface can be installed through an internal PCI/PCIe expansion connection. Use: Add or upgrade network connectivity in a computer. Benefit: Internal installation can provide a dedicated high - performance interface. Drawback: Requires a compatible slot and opening the computer.
  • Network interface device - USB: A network interface can connect through USB. Use: Add wired or wireless networking without an internal expansion card. Benefit: Portable and easy to attach/remove. Drawback: Uses a USB port and performance depends on the device/interface generation.
  • Air cooling: Moves heat away using heatsinks and airflow, commonly with fans. Use: Cool processors and other components. Benefit: Common, relatively simple and straightforward to maintain. Drawback: Fans can create noise and cooling is constrained by airflow and ambient temperature.
  • Liquid cooling: Transfers heat using a liquid loop and radiator. Use: Cool high-heat components. Benefit: Can move heat efficiently away from the component. Drawback: Greater complexity, cost and maintenance/leak considerations.
  • Sensors: Input components that detect physical or environmental conditions and convert them into data. Use: Monitoring and automated control. Benefit: Enable systems to react to real-world conditions. Drawback: Readings can be inaccurate or require calibration. Example: Temperature or light sensors in an embedded system.

Code-development tools 7.2.3

  • IDE: may provide code editing, debugging and screen-design tools.
  • Compiler: translates source code into another executable/machine-oriented form before execution.
  • Interpreter: translates/executes program instructions during execution.

Application software 7.2.4

Students must understand features and uses of word processors, spreadsheets, databases, email and project-management software.

Common misconceptionSystem software and application software serve different purposes. Do not describe an operating system as a normal end-user application.

Operating-system suitability

  • Batch operating system: Runs collections of jobs with little or no user interaction during processing; scheduling organises work. Use: Non-interactive, high-volume processing. Benefit: Efficient for repetitive bulk jobs. Drawback: Poor fit where immediate interactive response is required. Example: Large scheduled processing jobs.
  • Multitasking operating system: Supports concurrent execution by sharing processor time between tasks and responding to interrupts. Use: General-purpose interactive computing with multiple applications. Benefit: Users can work with several tasks apparently at once. Drawback: Tasks compete for processor and memory resources.
  • Real-time operating system: Designed to respond to events within defined timing constraints. Use: Monitoring, control and transaction-processing applications where timely response matters. Benefit: Predictable response supports time- sensitive tasks. Drawback: Often specialised and designed around strict requirements.
  • Network operating system: Provides network-focused services such as resource sharing, user management and communication. Use: Manage users and shared resources across a network. Benefit: Centralised control and resource access. Drawback: Requires administration and reliable network/server infrastructure.
  • Mobile operating system: Operating system designed for smartphones/tablets with mobile hardware, lower processing requirements and battery-life considerations. Use: Run mobile applications and manage portable-device hardware. Benefit: Optimised for portable, touch-oriented, battery-powered use. Drawback: Resource and platform restrictions can limit some desktop-style workloads.

Development tools in context

  • IDE - code editing tools: Tools for creating and editing source code, commonly with programming-oriented assistance. Use: Write and organise code within an integrated development environment.
  • IDE - debugging tools: Tools for investigating program behaviour and errors. Use: Locate and understand faults during development.
  • IDE - screen design tools: Tools that support designing user-interface screens. Use: Create or prototype the visual interface of an application.
  • Compiler: Translates source code into another form, commonly executable or machine-oriented code, before execution. Use: Prepare a whole program/build for execution. Benefit: Compiled output can execute without translating each source statement at run time. Drawback: Compilation is an additional build step and errors must be corrected and rebuilt.
  • Interpreter: Translates/executes source instructions through an interpreter at run time. Use: Run and test interpreted programs. Benefit: Supports rapid execution/testing without a separate full compile step. Drawback: Requires the interpreter environment and may have additional run-time translation overhead.

Application software: features and uses

  • Word processor: Application software designed for a common user task. Use: Create and edit formatted text documents.
  • Spreadsheet: Application software designed for a common user task. Use: Organise tabular data, calculate using formulae and analyse data.
  • Database: Application software designed for a common user task. Use: Store, organise, search and manage structured data.
  • Email: Application software designed for a common user task. Use: Create, send, receive and organise electronic messages.
  • Project management software: Application software designed for a common user task. Use: Plan and monitor project work, resources, tasks or schedules.

A defragmenter is relevant to applicable magnetic storage; do not recommend it as a general performance measure for every storage technology. Package managers support installation, updates, removal and dependencies.

Packets and packet switching 7.3.9

Data is divided into packets for network transmission. Students should understand packet contents/structure, the role of packet components, packet switching, causes of packet loss and CRC error handling.

Packet conceptsPacket information supports delivery and reconstruction of data. Packet switching allows packets to travel through a network rather than reserving one dedicated end-to-end path. Packet loss means expected packets fail to arrive. A cyclic redundancy check helps detect transmission errors.

Network protocols 7.3.10

GroupProtocolsRole
WebHTTP, HTTPSTransfer web resources; HTTPS provides protected web communication.
MailSMTP, POP, IMAPSMTP sends mail; POP/IMAP support retrieval/access approaches.
RoutingRIP, OSPFSupport routing decisions/exchange of routing information.
ApplicationFTP, SFTP, DHCP, DNSFile transfer, protected file transfer, network configuration allocation and name resolution.

Bandwidth and latency 7.3.11

  • Bandwidth: capacity for data transfer over a connection.
  • Latency: delay affecting how quickly data/response travels across a network.

Higher bandwidth can support more data transfer, while high latency can make interactive/networked systems feel less responsive. Suitability depends on the application.

Network types: full names and selection

  • PAN: Personal Area Network. LAN: Local Area Network. MAN: Metropolitan Area Network. WAN: Wide Area Network. VPN: Virtual Private Network.
  • PAN, LAN, MAN and WAN describe differing coverage scales. A VPN is a protected logical connection over another network, not a further geographic size category.
  • Compare user numbers, connection media and coverage. WAN connectivity can depend on carrier services; VPN performance still depends on its underlying connection.

Layer relationships and examples

OSI layerRelated functions/examples
ApplicationHTTP/HTTPS, SMTP, POP, IMAP, FTP, SFTP, DNS and DHCP.
PresentationData representation, translation, formatting; associated compression/encryption functions.
SessionEstablishing, managing and terminating application communication sessions.
TransportEnd-to-end transport and segmentation; TCP and transport ports.

PhysicalRaw-bit signalling using copper, fibre or radio.

In the four-layer TCP/IP model, application covers application-facing services; transport handles host-to-host transport; internet covers IP addressing/routing; network covers underlying link/physical access. Related examples are teaching mappings, not a claim that every real protocol fits a single simplified layer interpretation.

Packet structure, loss and CRC

  • A simplified structure comprises header/control information, payload and, where relevant to the protocol or framing, error-checking information. Actual fields vary; there is no universal packet format.
  • Header information supports delivery and processing. Payload carries the user/application data.
  • Packet switching sends separate packets through the network; the receiving system/protocol reassembles data as required.
  • Congestion, transmission problems and failed devices or links can cause packet loss.
  • CRC uses a calculated check value to detect corruption. It does not itself repair damaged data.

Bandwidth is capacity; latency is delay. High bandwidth can support large transfers while high latency still disrupts interactive responses.

7.4 Virtual Environments

Components 7.4.1

  • Virtual machines: software-defined computing environments, including virtual PCs, switches, routers and servers.
  • Type 1 hypervisor: virtualisation layer operating directly on host hardware.
  • Type 2 hypervisor: virtualisation software operating through a host operating system.

Features 7.4.2

FeatureMeaning in context
Increased securityVirtual boundaries can help separate workloads.
Managed executionVirtual workloads can be controlled within managed environments.
SharingPhysical resources can support multiple virtual environments.
AggregationResources can be combined/managed to support virtual workloads.
EmulationA virtual environment can represent another computing environment.
IsolationVirtual systems can be separated from one another.
PortabilityVirtual environments can be easier to move/reproduce than equivalent physical systems.

Benefits and drawbacks 7.4.3–7.4.4

BenefitsDrawbacks
Cost effectiveness for large environments; easy management; resilience; potentially lower carbon footprint; improved disaster-recovery options; better test environments; education/training provision.Extra hardware load; slower execution time; possible false representation of performance.
Judgement focusDo not assume virtualisation is always better. Apply resource demand, testing realism, resilience and management needs to the scenario.

Virtual components and hypervisor suitability

  • Virtual machine (VM): A software-defined computer environment with virtualised hardware resources. Use: Run a client or server operating environment on shared physical hardware. Benefit: Supports isolation, portability and flexible provisioning. Drawback: Consumes host resources and can introduce performance overhead.
  • Virtual client components: Virtual PCs, virtual switches and virtual routers model client systems and networking in software. Use: Build or test complete virtual networks without requiring equivalent physical devices.
  • Virtual server: A server operating as a VM rather than directly as a separate physical server. Use: Host server workloads on shared physical hardware.
  • Type 1 hypervisor: Runs directly on the physical host hardware and manages VMs. Use: Server/data -centre virtualisation. Benefit: Direct hardware control suits large virtualisation hosts. Drawback: Requires compatible infrastructure and administrative expertise.
  • Type 2 hypervisor: Runs as software on top of a host operating system. Use: Desktop testing, education and development. Benefit: Convenient on an existing computer. Drawback: Adds the host OS layer and typically has more overhead/dependence on it.

Benefits and limitations in context

  • Cost effectiveness for large environments: multiple virtual workloads can share physical infrastructure.
  • Easy management: virtual machines can be provisioned, copied and managed through virtualisation platforms.
  • Resilience: virtual workloads can be supported by redundancy and recovery arrangements.
  • Potentially lower carbon footprint: consolidation can reduce the number of physical systems required, although actual impact depends on implementation.
  • Improved disaster recovery options: VM images/backups can support restoration and relocation to suitable infrastructure.
  • Better testing environments: isolated systems can be created for software/system testing.
  • Education and training: learners can practise with isolated environments without requiring a separate physical machine for every scenario.
  • Extra hardware load: the physical host must supply processor, memory, storage and network resources to multiple virtual systems.
  • Slower execution time: virtualisation overhead and resource contention can reduce performance compared with a suitable dedicated physical system.
  • Potential false representation of performance: testing in a VM may not exactly reflect performance on the final physical or production environment.

7.5 Cloud Environments

Cloud types 7.5.1

  • Private cloud: cloud environment dedicated to an organisation or defined user group.
  • Public cloud: cloud services/resources supplied through a provider for customers to consume.

Benefits 7.5.2

  • Portability
  • Elasticity
  • Fewer storage limitations
  • Cost effectiveness

Cloud delivery models and responsibility 7.5.3

ModelClient managesCloud provider manages
IaaSApplication software, system software/middleware/OS, runtime, data, user accounts.Virtualisation and hardware: servers, network, storage.
PaaSApplication software, data, user accounts.Virtualisation, hardware, system software/middleware/OS and runtime.
SaaSUser accounts and data.Virtualisation, hardware, system software/middleware/OS, runtime and application software.
Common misconceptionThe client does not manage the same resources in IaaS, PaaS and SaaS. Responsibility shifts progressively towards the provider.

Cloud benefits explained

  • Portability: cloud-hosted services/data can be accessible from different suitable locations/devices subject to access and connectivity.
  • Elasticity: resources can be increased or reduced to respond to demand.
  • Fewer storage limitations: capacity can be expanded without installing local storage hardware for every increase.
  • Cost effectiveness: organisations can avoid some upfront infrastructure costs and consume provider resources, although cost advantage depends on usage and service model.

Private cloud is dedicated to one organisation and can offer greater control/customisation, with dedicated-environment costs and responsibilities. Public cloud uses provider infrastructure, offering flexible service consumption while creating provider, pricing and connectivity dependencies. Public cloud does not mean customer data is publicly accessible.

The responsibility table follows the reviewed source’s supplied specification split. Client responsibility for data and accounts remains across all three models; provider management of a technology layer does not remove every client responsibility.

7.6 Resilient Digital Environments

Benefits and impact 7.6.1

  • Increased security: data security in storage/transfer and reduced vulnerabilities.
  • Increased reputation: protection of brand/image and customer confidence.
  • Reduced downtime: supports continued availability of services.

Methods used to improve resilience 7.6.2

MethodPurpose/application
Software updates/upgradesPlanned updates/upgrades and patches responding to vulnerabilities.
Hardware replacementRolling replacement plans and secure disposal reduce dependence on ageing equipment.
Data/system redundancyAlternative copies/components reduce reliance on a single resource.
Device hardeningRemove unneeded ports, applications, permissions and access.
Backup/recoveryOnsite, remote/offsite and cloud approaches support restoration.
Hot/warm/cold sitesAlternative recovery locations providing different levels of readiness.
Standard operating proceduresInclude staff training, induction, new digital systems and new/updated policies.
Scenario linkHigher-demand questions should require students to select or judge resilience measures in relation to a stated risk, system requirement or organisational context.

Recovery readiness and organisational impact

Alternative siteReadiness and trade-off
HotHighly ready for rapid takeover; high standing cost and resource needs.
WarmSome prepared infrastructure; restoration/configuration still needed; balances cost and readiness.
ColdBasic alternative facilities; systems/data require setup; lower standing cost but slower recovery.

Backups support restoration; redundancy provides alternatives for continuity. They complement each other. Recovery procedures must explain how services/data will be restored. SOPs need staff training, induction, new-system guidance and updated policies. A backup alone does not guarantee a resilient service.

Revision-agent guidance

  • Use only the attached approved sources for subject content and marking; do not fill gaps using outside knowledge. Follow the shared specification where available; this reviewed teaching guide is not a replacement official specification.
  • CA7 means Digital Environments, Paper 2, references 7.1.1–7.6.2. Introduce CA8 security only where the approved CA7 sources explicitly require it.
  • Offer Revise a topic or Practise exam questions, then reveal topic/subtopic choices one step at a time. Use choices already supplied without asking again.
  • Networks must include PAN, LAN, MAN, WAN and VPN. Treat VPN as a logical connection rather than a geographic scale.
  • Finish teaching before retrieval. Use fresh contexts and keep checks separate from nearby answer-bearing examples.
  • Use open-response assessment only, one question at a time; no fixed question set, answer choices, leading hints, model answers or marking points before submission.
  • State marks with each question. Keep AOs and marking guidance behind the scenes unless requested after an answer.
  • After submission, give a concise mark, what earned credit and one improvement. Keep full marking points and model answers for the requested feedback option.
  • After marking, offer only Detailed marking, Model answer, Retry, Continue. Detailed marking explains awarded/withheld marks; Model answer requires explicit selection after an attempt; Retry invites a new response without additional marking points; Continue asks whether another question is wanted.
  • Do not advance automatically. If another question is declined, return to the two-option opening menu.
  • Accept technically equivalent wording. Credit explicit distinct valid points; avoid duplicated credit, vague unsupported claims and unearned scenario application. Separate first attempts from retries and identify support already seen.
  • Use indicative practice rubrics unless an applicable official scheme is provided. Do not invent official level descriptors or infer a qualification grade.
